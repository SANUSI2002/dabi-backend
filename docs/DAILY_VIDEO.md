# Daily consultations

Patient and verified doctor accounts join from their existing confirmed virtual appointment. The server checks the assigned participant, ACTIVE/email-verified identities, doctor approval, appointment state and scheduled time. The window is ten minutes before the start to fifteen minutes after the end. Joining requires an explicit provider notice acknowledgement. There is no test-account allowlist.

Set server-only `DAILY_API_KEY`, `DAILY_DOMAIN=sabihealth`, `DAILY_VIDEO_ENABLED=true`, `DAILY_PROCESSING_APPROVED=true`. Never place the key in Vercel/frontend variables. The application exchanges it for room-scoped participant tokens held only in browser memory. Metadata contains random room names and generic Doctor/Patient labels; no medical reason, email, patient name or prescription is sent by the server to Daily.

Rooms are private, two-person, time-bounded and enforce unique opaque participant IDs. Participants have no owner/admin privileges. Recording, transcription, screen sharing, shared chat history and advanced persistent chat are disabled. Daily Prebuilt supplies camera/mic controls, prejoin checks and live in-call text chat. This is not asynchronous/offline messaging and chat is not written to the Sabi medical record. Call audio/video and live messages are transmitted through Daily; a privacy notice does not substitute for the operator's legal/provider due diligence.

Rooms are lazily created on first join, reused safely and verified against their expected security settings. Requests revalidate the appointment after provider I/O. A durable room row supports periodic cleanup: every fifteen seconds the worker selects expired, cancelled/completed or account-disabled rooms, expires access, ejects/bans both IDs and deletes the provider room. Provider failures back off one minute; the room/token expiry is a hard fallback. Revocation is therefore eventually consistent, not instantaneous. The browser rechecks eligibility every thirty seconds and stops if it can no longer verify access. Closing the modal destroys the Daily frame, disconnecting camera/microphone; closing is not the same as marking the appointment completed.

Run `node scripts/check-daily.js` with server environment to verify private room creation, both participant tokens and cleanup without media or personal data. It emits only fixed status messages and safe error codes. Route/service/provider tests use synthetic fixtures; a two-browser doctor/patient call is still required for actual media and chat verification. Daily account limits/billing can prevent provider calls even when an API key exists. Do not claim paid add-ons, healthcare suitability or regulatory compliance without separate verification.

Doctor deployment remains within the existing telemedicine build at `https://telemedicine.sabihealth.org/doctor-portal` (the separate subdomain was deferred). `/api` is reverse-proxied using the shared `vercel.json`. No new trusted origin or domain-wide auth cookie is introduced; each portal establishes its own central Sabi session.
